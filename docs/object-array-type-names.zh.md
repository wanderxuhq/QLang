# 对象/数组类型名 —— 分析期可以推出什么

状态:研究笔记(实现之前)。它决定了 `.length` 这类成员规则的判据,以及「声明 vs 推导」一致性检查
的写法。背景见 `unboxed-values-handoff.md` §5⑥a/§5⑨:给库内部函数加 `: Object` 返回注解后,
**解释器**拒绝普通对象,而编译器只是**看起来**没事 —— 因为声明名等于推导名时它把返回边的检查证明
成死代码。

## 1. 现有形态(运行期与语言里的实际实体)

| 形态 | 运行期实体 | 是类型值吗 | 说明 |
|---|---|---|---|
| `Array`、`Object` | `__arr_ctor`、`__obj_ctor`(`aot/runtime.ql:1907-1908`) | **不是** | **构造器**:应用它派生出类型 —— `Array(T)`、`Object(schema)`、`Object(pred)`(`aot/runtime.ql:1033/1064/1099`) |
| `AnyArray`、`AnyObject` | `{check: __pred_array}` / `{check: __pred_object}`(`aot/runtime.ql:1347-1348`) | **是** | **具体类型**,与 `Number` 同级:成员允许任意类型 |
| `Array(T)` / `Object(...)` | 构造器产生的**新**类型值 | 是 | 每次应用得到**互不相同**的类型;其 `check` 强制元素类型 / schema / 谓词 |
| `[1, 2]` / `{a: 1}` | 普通数组/对象值 | — | 属于**族**;今天分析期把它命名成 `Array` / `Object`,即拿**构造器**的名字当值类型 |
| `Number` `String` `Boolean` `Null` | `typeScalar`(`aot/types.ql:12`) | 是 | 标量:单机器字,可解箱 |

第三行的直接后果:`Object.check` / `Array.check` **不存在** —— 这正是 `Object.check(o)` 在**两个引擎**
里都返回错误的原因(已用最小复现验证),所以那不是解释器 bug。

## 2. 两个 `AnyObject` 可以互换吗?(待研究的那一点)

**不能,`AnyArray` 同理。**「成员任意」描述的是**接受什么**,不是**知道什么**:分析期都叫 `AnyObject`
的两个值,成员类型可能不同;而来自 `Object(schema)` / `Object(pred)` 的值**比 `AnyObject` 更窄**。
方向很关键:

- `AnyObject` **接受**派生出来的对象值(它仍然是对象)⇒ 声明 `: AnyObject` 能被任意对象满足;
- 派生的类型**一般不接受** `AnyObject` 值 —— 它的 `check` 可能拒绝。那是**运行期**的裁决,不能是
  编译期错误。

所以对象/数组族**不是一张名字可互换的格**;对一个族值,编译期唯一能确定的事实是**「它属于这个族」**。

## 3. 因此分析期可以推出的结论

1. **只能推族属。** 从字面量、或任何类型是族成员的值,只能推出「数组」或「对象」,更窄的都不行。
   按族设定的成员规则(数组的 `.length -> Number`、对象上的键索引)可以据此生效。
2. **不做窄比较。**「声明 vs 推导」不一致检查对标量是可靠的(名字相等有意义),但在对象/数组族内
   **必须不触发**:派生注解与字面量、或两个不同的具体族成员,都只是「族内兼容」,其余交给运行期。
   在那里报编译错误会拒绝合法程序(而且它本来就会拒绝 stdlib 自己的注解)。
3. **应用的注解也要被认成族成员。** `annotationBuiltinName` 只解析**裸**内建名,所以
   `Array(Number)` / `Object({a: Number})` 现在解析为 "",注解是**惰性**的(没有检查、没有信息)。
   无论族判据最终长什么样,注解读取都得先能把「应用过的构造器」归入族。

## 4. 实现上的连带项(尚未动手)

1. 字面量的推导名:`tagType(node, "AnyObject")` / `"AnyArray"`,不再复用构造器名 `Object` / `Array`
   (`aot/types.ql:529/535`)—— 这样用**具体类型**做注解才与推导结果一致。
2. 族判据(`isArrayType(name)` / `isObjectType(name)`),用来替换下面几处的**名字相等**比较:
   - `.length -> Number` 规则(`aot/types.ql:585`);
   - 声明 vs 推导的一致性检查(`aot/types.ql:675`);
   - 注解读取器,扩展到「应用过的构造器」(`§3.3`)。
3. 复核这条链上的现有注解:`aot/runtime.ql` 的 4 处 `: Array` 返回(`__obj_keys`、`__num_frexp` …),
   以及用 `: Array(Number)` / `: Object({a: Number})` 的 fixture(`aot/tests/t13_bindings.ql:56/60`)——
   那是设计上**应有的写法**,必须继续可用。
