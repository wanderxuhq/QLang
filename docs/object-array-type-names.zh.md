# 对象/数组类型名 —— 分析期可以推出什么

状态:设计笔记,已与作者定稿。取代此前「格」的说法。
背景:`unboxed-values-handoff.md` §5⑥a/§5⑨(给库内部函数加 `: Object` 后**解释器**拒绝普通对象;
编译器只是**看起来**没事 —— 声明名等于推导名时它把返回边检查证明成死代码)。

## 1. 现有形态

| 形态 | 运行期实体 | 是类型值吗 | 说明 |
|---|---|---|---|
| `Array`、`Object` | `__arr_ctor`、`__obj_ctor`(`aot/runtime.ql:1907-1908`) | **不是** | **构造器**。没有 `check` 是**正常的**。它们的用途是派生类型:`Array(T)`、`Object(schema)`、`Object(pred)`(`aot/runtime.ql:1033/1064/1099`) |
| `Array(T)` / `Object(...)` | 构造器产出的**新**类型值 | **是,而且必须** | **构造器产出的东西必须是类型**(它带着强制元素类型 / schema / 谓词的 `check`) |
| `AnyArray`、`AnyObject` | `{check: __pred_array}` / `{check: __pred_object}`(`aot/runtime.ql:1347-1348`) | 是 | **具体类型**,与 `Number` 同级:成员允许任意类型 |
| `[1, 2]` / `{a: 1}` | 普通数组/对象值 | — | 属于**族**;分析期给它打一个**族标签**(今天用 `Array` / `Object`) |
| `Number` `String` `Boolean` `Null` | `typeScalar`(`aot/types.ql:12`) | 是 | 标量:单机器字,可解箱 |

所以「`Object.check` 不存在」不是缺陷 —— 构造器本来就该如此。真正的缺陷会是**构造出来的东西没有
`check`**,而这不是现状。

## 2. 规则(让这件事尘埃落定的简化)

**只有「指定类型」参与特判,其余一律装箱。**

- *表示*:一小撮指定类型走裸值/解箱(今天只有 `Number`)。其他一切 —— `AnyArray`、`Object(schema)`、
  `Array(Number)` 及任何派生 —— **永远装箱**。不需要排序、不需要格、不需要讨论互换性。这已经是
  现有 `staticRep` / `unboxType` 的形状。
- *静态一致性*:声明 vs 推导的比较**只在指定类型之间**有意义(那里名字相等才说明问题)。对象/数组
  族内**必须不触发**:两个 `AnyObject` 不可互换(成员类型不同;`Object(schema)`/`Object(pred)` 比
  `AnyObject` 更窄),编译期唯一确定的事实就是**族属**,更窄的都交给运行期裁决。

## 3. 还需要「判断」的只剩三处,且都是上述规则之外的具体问题

1. **成员规则用的族标签。** 数组接收者上的 `.length -> Number`(`aot/types.ql:585`)需要知道接收者
   是数组。它只需要**族标签**,不需要类型格 —— 而字面量今天拿到的标签就够用。
2. **应用过的构造器是类型。** `Array(Number)` / `Object({a: Number})` 是**合法注解**,必须被认成
   类型(这样它的 `check` 才会生效)。今天 `annotationBuiltinName` 只解析**裸**内建名,这些会解析成
   "" ⇒ 注解**惰性**(无检查、无信息)。这是要补的缺口,也是第 1 点能在「被注解的值」上生效的前提。
3. **裸构造器不是注解。** `: Array` / `: Object` 写的是构造器而不是类型 ⇒ 作为注解**无效** ⇒
   应当**编译期诊断**(「`Array` 是构造器,不是类型;请写 `AnyArray` 或构造式」),而不是静默惰性、
   也不是运行期才炸。这正是 §5⑥a 那个错误的成因,一条诊断就能当场抓住。

## 4. 实现清单

1. *(已删除 —— 把字面量的推导标签改成 `AnyObject`/`AnyArray` **不需要**:族内从不做静态比较。)*
2. 把「声明 vs 推导」一致性检查(`aot/types.ql:675`)限定在指定类型上。
3. 让注解读取器把**应用过的构造器**认成类型注解,`Array(T)`/`Object(...)` 不再惰性。
4. 对「裸构造器当注解」(`: Array` / `: Object`)报编译期诊断。
5. 修 `aot/runtime.ql` 那 4 处 `: Array` 返回 → `: AnyArray`;复核 `t13_bindings.ql:56/60` 的
   `: Array(Number)` / `: Object({a: Number})`(设计上应有的写法,必须继续可用)。
6. 成员规则(`.length`)继续用推导出的族标签。

**实测记录(两个引擎都跑了):** 那 4 处 `: Array` 返回**今天**没造成任何问题 ——
`std.Object.keys({a:1,b:2})` 在解释器和编译器下都返回正常数组(`isError` 为 false、`.length` 为 2)
—— 因为分析期给返回值推导出的是 `Array`,与声明名相等 ⇒ 返回边检查被证明成死代码、**从未发射**。
也就是说它们是**惰性**的而非有效检查,这恰好对应 §3.3。

顺序:2 → 4(小且自足)→ 3 → 5 → 回到 std 注解战役(对象/数组返回即可标注)。

## 5. 规则 2/4/5/6 落地后的实测,以及下一个要消掉的代价

已落地:族感知一致性检查(2)、构造器诊断(4)、4 处 `: Array` 返回 → `: AnyArray`(5)、
`.length -> Number` 改用族标签(6)。IR **±0**(`194812`),并且:

- `let x: Array = [1, 2];` ⇒ **CompileError**:「Array is a constructor, not a type: use AnyArray for
  any Array, or a constructed form like Array(Number)」(位置指向注解本身)。
- `: AnyArray` / `: AnyObject` 被接受;解释器那条常开的返回检查现在**通过**(`AnyObject.check`
  存在 —— 实测:把库标注后 `t19_literals` 重新打印 `true`)。
- **但是**给对象返回加注解要 **+164 行 IR**(两个函数,`194812` → `194976`):声明名 `AnyObject`
  与推导名 `Object` 永不相等 ⇒ 返回边检查永远不被判死 ⇒ 每个返回边都发一段(~82 行/处)。
- **让对象/数组注解变免费的下一步**:把发射器的 `proven` 判定扩展到族 ——
  `declared == "Any" + X && derived ∈ family(X)` ⇒ 检查是死代码。这是可靠的,因为 `AnyX` **接受**
  该族的每一个成员(这正是 `__pred_object`/`__pred_array` 的含义)。它是标量规则在族上的对偶,
  能把那 +164 消掉。
